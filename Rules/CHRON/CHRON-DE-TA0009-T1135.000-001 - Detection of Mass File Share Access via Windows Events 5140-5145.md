### **2. DETECTION OVERVIEW**

**Description:**

This detection identifies abnormal behaviour where a single user account attempts to access a high number of Windows file shares in a short timeframe. Such behavior may indicate reconnaissance, lateral movement, or automated scanning activities by a threat actor.

**Hypothesis:**

We hypothesize that an adversary attempting lateral movement (MITRE Technique T1135 - Network Share Discovery) will query numerous file shares using SMB. This will generate Windows Event Logs 5140 and 5145, which can be correlated to identify suspicious mass access attempts by a single account.

### **4. LOGIC & IMPLEMENTATION**

**Detection Logic (Pseudocode or SIEM Query):**

-- Provide the query here.  
-- Comment heavily to explain each logical step of the query.

```
rule mass_file_share_scan
{
  meta:
    author = "Lucian Peckham"
    description = "Detect high volume of Windows share access (Event 5140 / 5145) from single account"
    version = "1.0"

  events:
    $e = {
      udm.event_type = "SECURITY_EVENT",
      udm.event.security_event.id in { 5140, 5145 }
    }

  condition:
    // We want to correlate multiple events in a sliding window
    // Count total events and distinct share names per account, per computer
    // If above threshold, emit detection

    $e in last(1h) by $e.principal.user.userid, $e.source.hostname
    and
    count($e) > 100
    and
    dcount( extract($e.object_name, `\\\\.*\\(.+?)(?:\\.*)?$`, 1) ) > 1
}
```

**Known False Positives:**

- IT scripts or automation scanning legitimate shares
- Backup systems accessing network shares
- SCCM or similar tools performing inventory or distribution
- Antivirus or EDR agents querying shares for telemetry
- Pending Further Testing

- Filter on known service accounts or devices (e.g., backup servers, AV agents)
