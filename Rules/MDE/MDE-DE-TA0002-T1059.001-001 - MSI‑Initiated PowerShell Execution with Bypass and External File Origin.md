### **2. DETECTION OVERVIEW**

**Description:**

This analytic detects **suspicious MSI‑driven PowerShell execution** where `msiexec.exe` launches `powershell.exe` with **ExecutionPolicy Bypass**, scripted execution (`.ps1`), and installer‑style arguments, **correlated to an MSI downloaded from an external referrer URL**.


**Hypothesis:**

We hypothesize that an adversary leveraging **malicious MSI installers** for initial access or execution will:

1. Deliver an MSI from an external web referrer
2. Execute `msiexec.exe` to install the payload
3. Spawn `powershell.exe` with **ExecutionPolicy Bypass** and scripted arguments
4. Perform post‑install activity that exceeds expected installer behavior

This behavior can be observed through **correlated process creation and file download telemetry**.

### **4. LOGIC & IMPLEMENTATION**

**Detection Logic (Pseudocode or SIEM Query):**

-- Provide the query here.  
-- Comment heavily to explain each logical step of the query.

```
// Behavioral Query based on Behaviors Observed compared to Atomic Queries, 
// we first focus on the DeviceProcessEvents identifying the key artifacts observed during our analysis
// My hyptothesis is we will observe DeviceProcessEvents initiated by a DeviceFileEvents with the fileoriginurl set not to be empty 
let suspiciousProcess =
DeviceProcessEvents
| where InitiatingProcessFileName contains "msiexec.exe" and FileName == "powershell.exe"
// | where DeviceName contains "cltnbc2l34306w9"
| where ProcessCommandLine contains "-NoProfile -Noninteractive -ExecutionPolicy Bypass -File" 
and ProcessCommandLine contains ".ps1" 
and ProcessCommandLine !contains "-Uninstall"
and ProcessCommandLine contains "-propFile" and ProcessCommandLine contains "-scriptArgs"
// | where FileName contains "nsp145B.tmp.exe"
// | where InitiatingProcessFolderPath contains "ProductManualCenter"
// | where AccountName contains "nnghaswala"
| project ProcTime = Timestamp, DeviceId, DeviceName, AccountName, PS_ProcessId = ProcessId, ProcessCommandLine;
let DownloadEvent =
DeviceFileEvents
| where FileName contains ".msi" //or FileName contains ".exe"//"ProductManualCenter"
| project NetTime = Timestamp, DeviceId, InitiatingProcessId, FileOriginReferrerUrl, FileName;
suspiciousProcess
| join kind = leftouter DownloadEvent on DeviceId
| project ProcTime, NetTime, DeviceName, AccountName, ProcessCommandLine, FileName, FileOriginReferrerUrl
| where isnotempty(FileOriginReferrerUrl)
| order by ProcTime desc, NetTime asc

 
```

### Known False Positives

- Legitimate enterprise MSI installers that:
    - Invoke PowerShell during installation
    - Are downloaded via a web browser from external vendor sites
- Observed benign activity related to **Scribe installers** during the evaluation period

### Exclusion Strategy

- Exclude **signed MSI installers** from known, trusted vendors
- Exclude known benign installer paths once validated (e.g., enterprise software deployment tooling)
- Prefer exclusions based on:
    - Digital signature trust
    - Installation path consistency
    - Known internal software distribution infrastructure
- Avoid exclusions based solely on:
    - Process name
    - User account
    - Command‑line fragments alone
